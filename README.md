# LAB-01: Сетевая разведка и анализ трафика (Nmap & Wireshark)

## 1. Введение и Цель работы
**Объект исследования:** Анализ входящих и исходящих пакетов данных при сканировании тестового хоста `scanme.nmap.org`.
**Цель:** Изучить физику установления TCP-соединений, выявить паттерны автоматизированного сканирования и проанализировать служебные флаги на Транспортном (L4) и Сетевом (L3) уровнях модели OSI.

---

## 2. Инфраструктура Лаборатории (Environment)
Исследование проводилось в изолированной автономной Unix-среде со следующими параметрами:
*   **Хост:** Ноутбук DNS (Live-USB сессия на базе Ubuntu Linux, работа без постоянного накопителя SSD).
*   **Сетевой шлюз:** Мобильное устройство (в режиме USB-модема, распределение адресов по DHCP).
*   **Инструменты захвата и автоматизации:** `tmux` (мультиплексирование сессий), `tcpdump` (консольный перехватчик), `Wireshark` (графический сетевой анализатор).

---

## 3. Ход исследования и Перехват пакетов (Execution)

### Фаза 1: Сбор сырого трафика
В сессии `tmux` экран был разделен на две панели. 
1. В левой панели запущен скрытый фоновый перехват пакетов с сохранением дампа в энергонезависимую память флеш-накопителя:
   ```bash
   tcpdump -i <имя_интерфейса> -w /mnt/ventoy/scan_attack.pcap
   ```
2. В правой панели инициировано агрессивное сканирование популярных портов (Fast Mode) учебной цели:
   ```bash
   nmap -sS -F scanme.nmap.org
   ```

Всего за **~300 секунд** наблюдения система зафиксировала плотный поток трафика объемом **6000 пакетов**.

### Фаза 2: Анализ флагов в Wireshark
Для детальной отладки дамп `scan_attack.pcap` был импортирован в графическую оболочку Wireshark. Применены специализированные Display-фильтры.

1. **Поиск запросов на инициацию соединения:**
   Фильтр: `tcp.flags.syn == 1 && tcp.flags.ack == 0`
   Выявлена серия исходящих `SYN`-пакетов, направленных на перебор портов удаленного сервера.

2. **Анализ ответов периметра (Флаги сброса):**
   Фильтр: `tcp.flags.reset == 1`
   Зафиксированы критически важные маркеры поведения целевых узлов:
   *   **Узел `xxx.xxx.xxx.98` (scanme.nmap.org):** Вернул жесткие пакеты `RST` на порты **80 (HTTP)** и **443 (HTTPS)**. Физика процесса: порты определены системой как `Closed` (целевые веб-службы отключены, либо сработала запрещающая политика фаервола REJECT).
   *   **Узел `xxx.xxx.xxx.93` (Внутренний интерфейс):** Зафиксирован исходящий пакет `RST` на динамический порт **44106**, что свидетельствует о штатной принудительной очистке зависших фоновых сессий операционной системой в ОЗУ.

## 4. Заключение Blue Team (Mitigation & Выводы)
Эксперимент наглядно продемонстрировал разницу между штатным трафиком и поведенческими аномалиями автоматизированного сканирования. На основе анализа флагов `SYN` и `RST` подтверждена работоспособность механизмов фильтрации. 

**Рекомендации по защите периметра:**
Для предотвращения сканирования сети злоумышленниками рекомендовано внедрение технологий сокрытия портов (политика `DROP` вместо `REJECT` на брандмауэре) и фильтрация входящих `SYN`-пакетов, превышающих лимиты нормального поведения (Rate Limiting).
